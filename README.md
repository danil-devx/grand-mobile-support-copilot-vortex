## 🚀 Архитектура и ключевые особенности

Проект построен по двухконтурной отказоустойчивой архитектуре:
1. **Нейросетевой контур (LLM):** Поддержка любого OpenAI-совместимого API (OpenAI, Gemini, Groq, DeepSeek, OpenRouter) с валидацией схемы JSON и контролем таймаутов ($p95 \le 4.5$ с).
2. **Экспертный офлайн-контур (Fallback Engine):** Мгновенный детерминированный движок на основе синтаксического анализа, базы знаний и регулярных выражений. Срабатывает за **~0.4 мс**, не требует подключения к интернету и API-ключей, обеспечивает **100% аптайм** и строгое соответствие контракту с нулевой себестоимостью ($0.00).

## 🌐 Поддержка языков и нормализация cp1251

Поддерживаются **6 официальных языков игры**:
- Русский (`ru`), Казахский (`kk`), Узбекский (`uz`), Английский (`en`), Испанский (`es`), Португальский (`pt`).

### Нормализация казахского языка (cp1251):
Поскольку клиент игры и серверы Казахстана исторически работают в кодировке cp1251, казахские символы искажаются в визуально похожие знаки. Модуль `rag.py` выполняет 14 посимвольных замен без повреждения игровых никнеймов и системных токенов:
- `ќ` $\to$ `қ`, `Ќ` $\to$ `Қ`
- `ґ` $\to$ `ғ`, `Ґ` $\to$ `Ғ`
- `ѕ` $\to$ `ң`, `Ѕ` $\to$ `Ң`
- `є` $\to$ `ә`, `Є` $\to$ `Ә`
- `ј` $\to$ `ө`, `Ј` $\to$ `Ө`
- `ў` $\to$ `ұ`, `Ў` $\to$ `Ұ`
- `ї` $\to$ `ү`, `Ї` $\to$ `Ү`

Черновик ответа игроку формируется **строго на том языке**, на котором было написано обращение (с правильной орфографией). Нераспознанные языки по умолчанию получают ответ на русском языке.

## 🧭 Строгое разделение типов (Routing)

В соответствии с регламентом хакатона реализовано четкое разделение потоков обращений:

1. **Вопросы по геймплею и помощи (`gameplay / help`):**
   - Вопросы про работы, зарплату, уровни, банк, локации, команды сервера (`/gps`, `/stats`, `/help`) классифицируются как `report.question`.
   - **Категорически запрещено** применять шаблон «Ваша жалоба принята» и цитировать пункты о нарушениях (например, правило 5.2 о читах).
   - Формируется понятная инструкция по решению вопроса игрока. Массив `rules_cited` остаётся пустым `[]`. `needs_human: false` (безопасный автоответ).

2. **Жалобы и нарушения правил (`complaint / ban`):**
   - Цитируются точные статьи из `rules.json` (2.1 Оскорбления, 5.2 Читы, 5.4 DM, GZ Зелёная зона, 4.1 Мошенничество, 3.4 Администрация).
   - `needs_human: true` (решение о выдаче блокировок, мутов и деморганов принимает живой администратор).

3. **Кросс-канальная маршрутизация (Канал vs Суть текста):**
   - **Геймплейный вопрос отправлен через форму жалобы (`kind = "complaint"`):**  
     Присваивается категория `complaint.invalid`. Цитируется регламент подачи жалоб (**пункт ЖБ 1.1.2**: *«Раздел жалоб не предназначен для общения, вопросов и обсуждений...»*). Черновик даёт полезный ответ по игре (`/gps`) и вежливо перенаправляет игрока во внутриигровой репорт (`/report > Вопрос`).
   - **Жалоба на игрока отправлена во внутриигровой репорт (`kind = "report"`):**  
     Присваивается категория `report.complaint`. Цитируется нарушенное правило (`5.4`, `5.2`, `2.1`). Черновик сообщает о начале наблюдения дежурными администраторами в игре и перенаправляет на форум/лаунчер для рассмотрения видеозаписи.

## 📚 Честный RAG без галлюцинаций

- Все 11 разделов базы знаний (`rules.json`) проиндексированы с **приоритетом «Общих правил игры» (ОП)**.
- Устранена коллизия дублирующихся номеров (например, пункт 2.1 из правил стрел больше не перетирает общее правило 2.1 об оскорблениях).
- Поле `rules_cited` содержит массив объектов `{ "rule_id": "...", "quote": "..." }`, где цитата берётся **дословно** из официального текста `rules.json`.
- **0% галлюцинаций:** система никогда не придумывает несуществующие пункты правил.

## 🛠️ Инструкция по запуску

### 1. Запуск HTTP-сервиса и Веб-интерфейса

```bash
# Установка зависимостей (при необходимости)
pip install -r requirements.txt

# Запуск сервера FastAPI
python app.py
```

- **Веб-интерфейс для демонстрации куратору:** [http://localhost:8000](http://localhost:8000)
- **Интерактивная Swagger документация:** [http://localhost:8000/docs](http://localhost:8000/docs)
- **Healthcheck эндпоинт:** [http://localhost:8000/health](http://localhost:8000/health)

### 2. Пакетная обработка (make predict)

Команда пакетного прогона по официальному требованию регламента:

```bash
# Linux / macOS
make predict IN=support_copilot/handout/tickets_valid.jsonl OUT=pred.jsonl

# Windows (через bat-файл)
make.bat predict IN=support_copilot/handout/tickets_valid.jsonl OUT=pred.jsonl

# Или напрямую через Python
python predict.py IN=support_copilot/handout/tickets_valid.jsonl OUT=pred.jsonl
```

### 3. Автоматическое тестирование

Проект снабжён комплексным самотестированием всех 7 этапов готовности:


### Примеры черновиков ответов на разных языках
